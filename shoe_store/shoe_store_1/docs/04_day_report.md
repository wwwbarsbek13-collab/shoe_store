## Принятые решения
- **Порядок создания:** справочники → пользователи/товары → позиции → заказы → состав. FK не может ссылаться на несуществующую таблицу.
- **RESTRICT** для ролей, пользователей, товаров, размеров — защита от случайной потери данных.
- **CASCADE** для order_items при удалении order — состав не имеет смысла без заказа.
- **REAL для size_value** — размеры могут быть дробными (36.5).
- **TEXT для order_date** — SQLite не имеет отдельного типа DATE; ISO 8601 обеспечивает сортировку.
- **8 индексов** — на все FK (ускоряют JOIN) + на дату заказа и категорию (сортировка/фильтрация).
