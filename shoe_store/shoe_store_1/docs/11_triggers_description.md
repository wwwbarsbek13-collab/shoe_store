# Отчет по триггерам и аудиту 

## 1. Созданные триггеры

| Триггер | Событие | Назначение |
|---------|---------|------------|
| `trg_audit_price_update` | AFTER UPDATE ON products | Логирует изменение цен в `audit_log` (только при реальном изменении). |
| `trg_audit_order_delete` | AFTER DELETE ON orders | Логирует удаление заказов. |
| `trg_users_updated_at` | AFTER UPDATE ON users | Обновляет поле `updated_at` при изменении пользователя. |
| `trg_stock_auto_decrease` | AFTER INSERT ON order_items | Списывает остаток со склада при добавлении в заказ. |
| `trg_prevent_user_delete` | BEFORE DELETE ON users | Запрещает удаление пользователя с заказами. |
| `trg_check_negative_quantity` | BEFORE INSERT ON stock_items | Запрещает отрицательный остаток. |

## 2. BEFORE и AFTER

| Тип | Когда срабатывает | Пример |
|-----|-------------------|--------|
| **BEFORE** | До изменения. Может отменить операцию через `RAISE(ABORT)`. | Проверка на отрицательный остаток. |
| **AFTER** | После изменения. Используется для логирования и каскадных обновлений. | Запись в `audit_log` при смене цены. |

## 3. OLD и NEW

- `OLD` — старые значения (до изменения). Доступен в `UPDATE` и `DELETE`.
- `NEW` — новые значения (после изменения). Доступен в `INSERT` и `UPDATE`.
- В триггере на `DELETE` `NEW` недоступен, так как строки уже нет.

## 5. Защита от удаления

Триггер `trg_prevent_user_delete` проверяет наличие заказов у пользователя. Если они есть — вызывается `RAISE(ABORT, 'Нельзя удалить пользователя с активными заказами')`.

## 7. Ответы на вопросы

1. **Триггер vs Процедура:** триггер срабатывает автоматически по событию, процедуру вызывают явно.
2. **Почему в SQLite нет сложного языка:** SQLite компактный, сложная логика выносится в приложение.
3. **BEFORE vs AFTER:** BEFORE — до изменения (можно запретить), AFTER — после (для логов).
4. **Что будет без `WHEN OLD.price != NEW.price`:** журнал будет заполняться даже при неизменной цене.
5. **Зачем OLD и NEW:** для доступа к старым и новым значениям строки.
6. **Почему в DELETE нет NEW:** строки уже не существует.
7. **Как прервать операцию:** `RAISE(ABORT, 'текст')`.
8. **Зачем audit_log:** для отслеживания изменений (кто, что, когда).
9. **Как обновить остатки:** `UPDATE stock_items SET quantity_available = quantity_available - NEW.quantity`.
10. **Что будет при удалении таблицы:** триггеры удалятся вместе с ней.
