## 1. Роли и права в SQLite

В SQLite нет встроенных пользователей и паролей, как в PostgreSQL. Разграничение прав реализуется на уровне приложения (Python). Создана таблица `roles` с тремя новыми ролями: `admin_db`, `developer`, `reader`. Словарь `PERMISSIONS` связывает роли с допустимыми действиями.

| Роль | Действия |
|------|----------|
| `admin_db` | SELECT, INSERT, UPDATE, DELETE, CREATE, DROP |
| `developer` | SELECT, INSERT, UPDATE |
| `reader` | SELECT |

## 2. Функция check_permission и результаты тестов

Функция `check_permission(conn, user_id, action)` получает роль пользователя из БД и проверяет, есть ли действие в списке разрешенных.

**Результаты:**
- `admin_db` (DELETE): **True**
- `reader` (DELETE): **False**
- `reader` (SELECT): **True**

## 3. Способы резервного копирования

| Метод | Плюсы | Минусы |
|-------|-------|--------|
| `shutil.copy` | Простота. | Риск получить «битую» копию, если в момент копирования идет запись. |
| `conn.backup()` | Безопасно, даже при активных транзакциях. | Чуть сложнее в коде. |

## 4. Проверка целостности

`PRAGMA integrity_check` вернул `ok`. Это значит, что база не содержит битых страниц и ошибок.

1. Создан бэкап через `backup_simple()`.
2. Удалены все заказы (симуляция сбоя).
3. Вызвана функция `restore(backup_path)`, которая скопировала файл бэкапа обратно.
4. После восстановления заказы вернулись.
